# Windows run: 3k. Alerts (test/win-3k-1)

yagura 0.58.15, release build, Windows 11 x64, isolated config/state. Not elevated.
The system toast was read from the notification database
(`%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db`, copied with its WAL, queried with Python's sqlite3):
rows of handler `uchmk.yagura`, with arrival time and the toast's text. The UI language is Japanese (common.toml: auto),
so the titles read "CPU が 0% を超えました" (the translation of "{0} is over {1}"), and a rule's own `name` shows as it is.

## Ticked

- **3k.1** `[x]`. Rule `cpu above=0 for=0`. Started yagura: one toast in the DB 1.4 s later (21:07:12.3, start 21:07:10.9),
  the status bar showed "CPU が 0% を超えました: CPU は DESKTOP-7UBRVG9 で 5%" (picture o2\t1.png), and no second toast in the next 8 s
  (also none in the 6 s after). Config rewritten to `above = 100`: 0 toasts in 6 s. Rewritten back to `above = 0`: 1 toast within about 1 s (21:08:03.2).
  (An earlier run with three yagura windows alive gave three toasts at that step, one each; the clean single-window run gave one.)
- **3k.4** `[x]`. Proxy for "network off": the webhook (`json` format) pointed at 127.0.0.1:18099 with nothing listening.
  Fired at 21:08:54; a listener started at 21:09:04 got exactly one POST at 21:09:27 (about 30 s after the fire), body with `"state": "alert"`.
  With the listener started only at 45 s (after the retry), nothing arrived in the next 60 s: once only.
- **3k.6** `[x]`. config.toml with `metric = "fans"`, a rule with both `above` and `below`, and a good rule (`name = "good rule"`).
  `yagura env`: "alerts : 1", warning 1 (`metric` is one of ...) and warning 2 (needs one number, `above` or `below`);
  the settings screen's 詳細 page lists the same two warnings under 警告 (o6b\adv.png). The good rule's toast "good rule" is in the notification DB.
- **3k.7** `[x]`. Proxy for a second machine: `yagura --agent` (port 17313, own config) and `[[host]] addr = "127.0.0.1:17313"` in the viewer.
  `F`, `l`, Enter: State says `machine: loop`. With the rule at `above = 100` no toast; the rule edited to `above = 0` while `machine: loop`
  was still shown (State remote2 again `machine: loop`): one toast at 21:12:40. The same code path as a real second machine,
  but the host is this machine.

## Left `[ ]`

- **3k.2** Sound: `MessageBeep` through the speakers (`sound.rs`). Nothing on disk or screen changes; I cannot read audio, and focus mode cannot be toggled from here. A person's ears.
- **3k.3** The webhook against the real targets (a phone with the ntfy app, a Slack incoming webhook) is not reachable from here, and sending to
  public ntfy.sh publishes text. With a local listener the requests were right:
  ntfy: headers `Tags: warning`, `Priority: high`, `Title` set, body the alert text;
  slack: `Content-Type: application/json`, `{"text": "*<title>*\n<body>"}`;
  json: `{"title", "message", "folder", "state": "alert"}`. The phone/Slack display is the owner's.
- **3k.5** Stopping `Spooler` needs elevation (this session is not elevated: `IsInRole(Administrator)` False). It is a `needs-pc` row.
